# 技术决策与路线图

## 技术决策记录

### 为什么选择 SQLite？

**优点：**
- 零配置，单文件数据库
- 嵌入二进制，无外部依赖
- 适合中小流量（日上报 < 10 万）
- GORM 支持良好，未来可切换

**缺点：**
- 并发写入有锁竞争
- 不适合大规模分布式部署

**扩展路径：** 通过 GORM 抽象层，可切换到 PostgreSQL，只需修改数据库连接配置。

### 为什么使用 HMAC 签名而非 API Key？

- 防止请求被篡改（签名覆盖完整请求参数）
- 支持时间戳验证（防止请求重放）
- 支持 Nonce 验证（防止重复提交）
- 标准协议，多语言实现成熟

### 为什么 Dashboard 嵌入后端？

**优点：**
- 单二进制文件部署，运维简单
- 避免跨域配置问题
- 减少生产环境的外部依赖

**代价：**
- 前端必须先构建，后端才能编译
- 前后端构建流程耦合

### 为什么使用异步队列上报？

- 不阻塞主业务逻辑
- 失败重试不影响服务可用性
- 削峰填谷，保护数据库
- 队列满时丢弃，避免内存无限增长

## 路线图

### 短期计划

- [ ] 告警通知：错误频率超过阈值时发送 Webhook（钉钉/企业微信/Slack）
- [ ] Source Map 支持：上传 Source Map，服务端还原堆栈为源码位置
- [ ] 多应用动态配置：通过 API 管理应用配置，而非配置文件
- [ ] 数据导出：导出错误列表为 CSV/JSON

### 长期计划

- [ ] 多语言 SDK：Python、Java、Node.js
- [ ] 分布式部署：支持 PostgreSQL + Redis
- [ ] 用户权限管理：RBAC 权限控制
- [ ] 错误分组：智能聚合相似错误
- [ ] 趋势分析：错误趋势预测、异常检测
